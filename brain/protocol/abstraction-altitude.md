# Abstraction altitude

Name the reusable pattern, not the product, vendor, or PR that revealed it.

1. Draft the lesson, then delete proper nouns (service names, repo names, ticket IDs). If it still teaches the next different task, the altitude is right.
2. Prefer a portable `principles/` or `workflow/` note over a vendor-titled `codebase/` note when the failure mode generalizes.
3. Keep instance facts as a one-line example under the pattern, or in `codebase/` only when the constraint truly does not generalize (shared prod index IDs, repo-specific QA bans, etc.).
4. Trigger technology is evidence, not the title.
